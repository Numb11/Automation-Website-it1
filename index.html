What we build

Software for one organisation, around the records it already has.

  • Private search

    Find a passage in the organisation’s own records. The citation is a document they hold.

  • First draft

    A draft from those records, for a person there to edit before anyone relies on it.

  • Desktop applications

    The daily job, as software their staff open on the machines they already use.

  • Mobile applications

    The same work on a phone, with a named limit on what the phone can reach.

  • Websites

    A public site, or a private form, that is not a store for a client file.

  • Internal tools

    A repeated task taken out of a spreadsheet and put into a tool the organisation owns.

  • Integrations

    A join between systems they already run, without pasting the file into a public tool.

  • Databases and reporting

    The records in one place, an import that can be checked, and a report a person can read.

  • Accounts and logs

    Who can open the system, and a record of who used it.

  • Data cleaning

  • Desktop applications

How the data is handled

  • Their infrastructure

    The system runs on computers the organisation controls, or on one machine kept for that organisation.

  • A person decides

    Someone at the organisation chooses what is used. The software does not act on its own.

  • UK GDPR and the EU AI Act

    Each system is documented for the duties that apply to it: where personal data sits, who can see it, and how the AI system is described. There is no certificate that makes a firm compliant with either.
